# memorydb

MemoryDB Redis cluster with TLS and a named ACL user, shaped after prod Next
`impel-next-sea` in [`docs/prod-sea-mapping.md`](../../docs/prod-sea-mapping.md).

This is **not** interchangeable with [`valkey`](../valkey/). Next's client is
`ioredis.Cluster` with username `impel-next`. Valkey in this estate is
cluster-mode off and a default AUTH token.

## Creates

- `aws_memorydb_cluster` (Redis, TLS, cluster configuration endpoint)
- `aws_memorydb_user` + `aws_memorydb_acl`
- KMS CMK and alias, encrypting the cluster at rest and the password secret
- Subnet group
- Security group accepting `:6379` from `allowed_security_group_ids`
- Password — generated by `random_password`, stored in Secrets Manager as a
  **plain string** (not JSON)

## Call

```hcl
module "next_memorydb" {
  source = "../../modules/memorydb"

  name        = "impel-next-${var.environment}"
  description = "Durable Next Redis authority."
  vpc_id      = module.vpc.vpc_id
  subnet_ids  = module.vpc.private_subnet_ids

  node_type              = "db.t4g.small"
  num_shards             = 1
  num_replicas_per_shard = 0
}
```

Inject the password as the whole secret (Next reads `IMPEL_REDIS_PASSWORD`):

```hcl
environment_variables = {
  IMPEL_REDIS_AUTHORITY = "aws"
  IMPEL_REDIS_HOST      = module.next_memorydb.cluster_endpoint
  IMPEL_REDIS_PORT      = tostring(module.next_memorydb.port)
}

container_secrets = {
  IMPEL_REDIS_PASSWORD = module.next_memorydb.password_secret_arn
}
```

## The password

MemoryDB has no equivalent to RDS's `manage_master_user_password`, so the
password is generated by Terraform and **does land in state**. The state
bucket is CMK-encrypted and reachable only through the plan and apply roles —
treat anyone who can read it as holding this password.

Rotating means tainting `random_password.this` and restarting the consuming
services.

`special = false` matches prod CDK `excludePunctuation` and MemoryDB's
password character rules.

Do not JSON-wrap the secret. Prod injects `generateSecretString` as the entire
secret value.

## Notes

`allowed_security_group_ids` is fine when nothing flows back from the cluster
to the client. When a service also consumes an output of this module —
`kms_key_arn` for its execution role, or `cluster_endpoint` for its
configuration — that direction creates a dependency cycle. In that case leave
`allowed_security_group_ids` empty and grant access from the service side with
the `ecs-service` module's `data_store_ingress`.

The application username is `impel-next` and is hardcoded in Next
(`src/lib/storage/aws-redis.ts`). Changing `user_name` without changing the
app will fail cache health checks.
